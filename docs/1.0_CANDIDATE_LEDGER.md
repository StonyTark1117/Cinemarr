Cinemarr CI run on the exact final commit, matching local/hosted artifacts,
current acceptance evidence and consolidated branches. No tagging, publication
or release creation is authorized. An intermediate push or passing subset does
not complete this goal. Repeated test failures remain implementation work.

Jammarr's green hosted runtime suite uses a private D-Bus, PipeWire,
WirePlumber and PipeWire-Pulse graph for each gate. Cinemarr had instead used
the runner's shared PulseAudio daemon and OpenAL through an ALSA bridge with
a 512-frame period. The acceptance harness now starts and owns a private graph
before graphical clients, restores its original environment at teardown, uses
Jammarr's 48 kHz/1024-frame/eight-period OpenAL configuration, and directs
legacy LWJGL OpenAL to its measured Pulse sink. Hosted CI installs the same
audio services and no longer starts a shared daemon. A local preflight proved
the private socket and null-sink path and verified both successful and failed
teardown. The packaged real-Plex and lifecycle gates now explicitly enter the
same graph before creating measured sinks. Full runtime, real-Plex and hosted
results for this change remain open.

The private-graph NeoForge 1.20.1 independent-display diagnostic passed its
full three-TV, reload, reconnect, physical PCM and clean-shutdown checks.
Direct original-image review found distinct coarse/detailed rasters after
reload. Its sink captures carried the expected program tones with 20 ms
calibrated lag. A source-frozen `eb1dc06` Fabric 26.1.2 independent-display
run also passed all three-TV phases and shutdown without the earlier native
abort; physical PCM lag was 20 ms. Its scaled controller and paused/resumed
rasters were directly reviewed. The `0060dea` legacy main run passed with
unchanged-source receipt, direct Pulse sink inputs, 997 Hz capture on both
clients and zero measured lag. These are scoped diagnostics because further
harness changes follow, not substitutes for the final two legacy runs.

Jammarr also routes protocol and command probes through OpenAL's null backend:
those probes test networking and UI, while playback clients retain measured
sinks. Cinemarr now makes the same distinction, with an explicit diagnostic
override. Final hosted and local runtime validation of that change is pending.

Run `35746890575` on `1ac80ff` passed all sixteen hosted runtime jobs and the
aggregate 1.0 gate. Its downloaded bundle exposed a local byte-parity defect:
eleven JARs matched a forced local build, while five Forge/NeoForge JARs differed
only in nested core-JAR ZIP permissions. Gradle 8 had carried the local `0664`
umask into those entries; hosted entries were `0644`. The core archive now fixes
file and directory permissions, and release inspection rejects permission drift
inside nested core JARs. Two forced Gradle 8.8 core builds under `0002` and
`0022` produced the same bytes as the hosted core; a canonicalized NeoForge
archive with that core also matched the hosted JAR exactly. Because this repair
changes the source commit, the green `1ac80ff` run is diagnostic evidence and
all final-commit gates remain open.
