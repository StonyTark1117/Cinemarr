# Cinemarr 1.0 release hardening plan

## Current assessment

**1.0 prerelease under hardening — not a release candidate.**

The maintained scope is sixteen artifacts and twenty-one runtime profiles.
The original ten phases below remain required, together with the complete
[Custom TV display controls and independent streams specification](1.0_CUSTOM_TV_DISPLAY_PLAN.md).
Every requirement in that specification is mandatory for 1.0, including Forge
1.7.10; its feature work and certification cannot be deferred past this plan's
final completion gate. The two supplied requirement documents were identical;
the linked specification preserves their full text.

The earlier V11 candidate's 843-input snapshot is superseded by the integrated
feature work. The checkout is changing and is not a frozen release candidate.
Earlier successful runs certify only their recorded source and artifact bytes;
they cannot certify the new display settings, protocol, rendering, or stream
ownership. Reviewed incremental changes are being committed and pushed;
the remaining implementation is in progress and has not passed final acceptance.
The latest integrated code candidate is `9075937`; hosted verification run
`34530641372` completed with failure. Manifest validation passed; nine profiles
completed successfully and seven failed (five Fabric runtime/observer cases,
Forge 1.7.10 terminal lifecycle, and NeoForge 1.21.1 terminal lifecycle).
No final runtime box is closed from this run.
The downloaded 1.7.10 diagnostic nevertheless records an 8-second physical audio pair with zero lag and 0.998006 correlation; its terminal/lifecycle assertion still failed, so that evidence does not close the profile.

The Proxmox control plane, DiscPanel, and Plex endpoints are reachable, and the existing DiscPanel/Plex configuration can be reused. The retained guest is inventory-visible through Proxmox (VM 143), but its SSH password/key path is unavailable from this checkout and its guest agent did not answer execution requests; retained-guest staging and checks remain open.

The earlier V11 correction assigns an independent Plex playback identity to each
transcode, requests its decision before starting HLS, and sends the authoritative
playing/paused timeline every ten seconds and on pause changes. A separate
bounded worker queue coalesces reports. Stop serializes with an in-flight report,
prevents later reports, and releases the transcoder even if its final report
fails. Failed initial playlists also release their allocated session. The
[official Plex PMS API](https://developer.plex.tv/pms/) describes this lifecycle.

The actual preceding production classes reproduced a video HTTP 404 after a
successful Jammarr download. The corrected production-class sequence passes
five starts, four replacements, fifteen timeline reports, a Jammarr download,
and a subsequent video fetch. This accepts the combined correction, without
claiming that the diagnostic isolated each component's contribution.

Jammarr's reviewed release history at `8eccf06e972689315932072dd42aab7c4ff315a8`
contains relevant duplicate-ACK, retry, stale-window and bounded-work changes.
Its client health messages are separate from Plex timeline reports. Its released
Plex service downloads bounded MP3 files; the reviewed history provides no Plex
heartbeat implementation to transplant. No Jammarr code or deployed mod changed.
The separate fresh target-feasibility review remains deferred until all final
release work below is complete.

## Required display and stream work

The linked specification is normative in full. This checklist assigns its work
to the existing phases; it does not replace or narrow the detailed requirements.
All boxes remain open until verified on the integrated implementation.

| Required work | Owning phases | Evidence needed before closure |
| --- | --- | --- |
| Persistent settings and migration | 4, 7, 8 | Java 8-compatible settings/revisions; custom and Quick origin migration including unloaded controllers; schema migration preserving registrations and recovery records; reactivation/restart tests |
| Atomic commands and protocol migration | 3, 6, 8 | Permission, origin, dimensions, enum and revision validation before mutation; stale presentation-generation rejection before writes; protocol advanced from 10 consistently across adapters, manifest, fixtures, mismatch probes and documentation |
| Independent TV streams and capacity | 5, 8 | Shared timeline plus distinct TV stream identities throughout transport/client pipelines; same-TV viewer sharing, sibling isolation, deduplicated FIFO admission, bounded replacement/retirement and cleanup tests |
| Resolution and exact raster rendering | 4, 7, 8 | Aspect-preserving bounded resolution policy; explicit choices bypass tiny-screen Auto optimization; independently computed golden colors and captured block interiors; paused redraw, masking, allocation and texture lifecycle checks |
| Display Settings interface | 7, 8 | Dedicated page at 320×240 scaled viewport; Apply/Cancel, custom input validation, permissions, Quick locks, pending/errors and requested/effective quality; direct original capture review |
| Fresh complete release evidence | 8, 9, 10 | Feature smoke on all 21 profiles; deeper supplements on legacy/modern boundaries and every distinct rendering adapter; two identical builds, native guests, real Plex, final commit gate and hosted artifact parity |

- [ ] New custom TVs default to **Fit, Detailed, Auto**; existing custom TVs retain layout and detailed appearance. Layout, mapping and resolution remain independent controls.
- [ ] Quick TV construction footprints, presets, existing layout controls and build modes remain intact; mapping is Detailed and resolution is locked to the preset on the server.
- [ ] Custom resolution accepts 2–8192 per axis only within the decoded RGBA budget. Requests are source-aspect-preserving bounding boxes, subject to source quality, no upscaling, server caps and safe even dimensions. Report measured effective dimensions and limits.
- [ ] Layout/mapping changes redraw only the target TV without restarting Plex, including its retained paused frame. Live resolution changes replace only that TV's stream at the shared current timeline; idle/paused choices wait for the next start. Failed replacement preserves working playback where possible and exposes the error without retrying permanent failures indefinitely.
- [ ] Shared play/pause/resume/seek/queue/stop and track selection reach the relevant streams. Separate timeline/stream generations reject stale completion after seek, stop, item change or retune; one TV's failure cannot stop healthy siblings or conflate textures/positional audio.
- [ ] The existing configured stream cap counts active/reserved TV streams without automatic increase. Eligible TVs queue once in FIFO order, show “Waiting for stream capacity,” and start at current position when admitted. Retune, removal, viewer loss, pause and stop cancel obsolete reservations/requests.
- [ ] Preserve unique Plex identities, ten-second timeline reporting, serialized stop/report behavior, paused-transcode release, transfer bounds, viewer grace and shutdown cleanup through the ownership refactor.
- [ ] Removing a TV cancels its pending capacity/start work and closes its own Plex stream without stopping healthy sibling streams. Removing the final TV also checkpoints the shared watch-party timeline and leaves no owned media resources.
- [ ] Pixel mode samples one cell-center bilinear color per block into the full bounding raster, applies layout once, uses opaque black Fit bars, nearest filtering without mipmaps, and the existing hole mask/batched mesh. Reuse bounded buffers and release retained frames/textures across mode changes, retirement, reload and shutdown.
- [ ] Complete every deterministic, platform, UI, runtime and real-Plex acceptance requirement in the linked specification, including sparse/odd/large raster shapes, capacity failure/admission and Quick TV rollback/persistence.
- [ ] User documentation distinguishes block size, pixel mapping, requested/effective quality and per-TV capacity consumption. Redacted diagnostics identify TV stream, generations, requested/effective resolution, mapping, waiting status and bounded resources.

## 1. Restore truthful prerelease status

- Downgrade all release-ready claims to "1.0 prerelease under hardening."
- Record the exact failing Cinemarr run and identify completed, failed, and skipped gates.
- Preserve the current 16-artifact/21-runtime scope rather than importing Jammarr's version expansion.
- Define three distinct target states: builds, launches, and runtime-certified. Only runtime-certified targets may be advertised as supported.

Completion criteria:

- Documentation, GitHub status, and local evidence no longer contradict one another.
- No document describes the current commit as release-ready while a required gate is red or skipped.

The fresh `releaseMatrixGate` at `faadf87` passed artifact, GameTest and
preflight checks but stopped at `verifyPrivateXvfb`: this host has no `Xvfb`
binary, so its ten private-display cases failed before runtime launch. Keep
that gate red until it runs on a host with the required display server.

## 2. Fix the known 1.21.1 NeoForge A/V failure without weakening the gate

- Convert the downloaded CI failure into a reproducible regression case.
- Account for the observed failure correctly: both clients remained synchronized within approximately 10 ms until the 60-second fixture ended, then normal buffer exhaustion was counted as an underrun while the gate still required another eight-second stable-playback window.
- Distinguish normal end-of-stream from starvation during active playback.
- Give the fixture enough playback runway for every control operation and stability window.
- Continue requiring zero post-startup underruns and starvations while playback is active.
- Do not retry runtime failures merely to obtain a green result.
- Add explicit tests for active starvation, normal EOS, queue advancement, stop, seek near EOS, and follower reconnect near EOS.

Completion criteria:

- Repeated local `1.21.1-neoforge` runs pass.
- Injected starvation still fails the gate.
- Normal EOS produces a clean terminal transition without being misreported as active-playback starvation.

## 4. Consolidate duplicated platform sources

- Consolidate byte-for-byte-identical sources shared by the 1.20.1/1.20.2 family and the 26.1.2/26.2 family into family-shared source sets.
- Keep Minecraft-version and loader differences in narrow adapter or shim modules.

Completion criteria:

- Platform adapters remain thin and contain only genuine loader/version differences.

## 5. Bound asynchronous work and transport resources

Include the per-TV ownership and capacity requirements in the linked feature
specification. A bounded shared-session implementation alone cannot close this
phase: prove separate TV streams, fair admission, sibling isolation and bounded
replacement/retirement while preserving the existing Plex lifecycle corrections.

- Replace modern and legacy unbounded fixed-thread-pool queues with a shared bounded executor.
- Define limits for queued Plex metadata work, playback starts, segment fetches, retries, and decoder/probe work.
- Surface overload as a redacted, actionable response and diagnostic counter.
- Add generation and cancellation ownership so late browse, start, restart, seek, or segment completions cannot mutate a superseded session.
- Ensure shutdown rejects new work, cancels pending work, closes returned media handles, and drains main-thread completions safely.
- Introduce fair video egress scheduling with per-client, per-session, and global item/byte limits plus bounded per-tick draining.
- Ensure one client cannot monopolize segment delivery.
- Bound cached segment bytes as well as entry count; cap indexes, concurrent fetches, retry delay, retained buffers, and file/HTTP resources.

Completion criteria:

- Overload, cancellation, disconnect, restart, and server-stop tests prove bounded queues and memory.
- Stale completions cannot publish state or media from an obsolete generation.
- No media handles, executors, buffers, or transfer grants survive their owning lifecycle.

## 6. Strengthen protocol negotiation

The display/stream wire changes require a deliberate advance from protocol 10.
Carry distinct timeline and TV stream identities and generations through every
applicable packet and client pipeline; add atomic display-settings validation
and the stale-presentation ordering regression to the security coverage.

- Preserve Cinemarr's required-client policy; Jammarr's optional-client behavior does not fit clients that must render and decode television media.
- Extend hello negotiation with explicit feature bits and negotiated limits for chunk size, transfer window, and health reporting.
- Reject incompatible or excessive peers consistently across Fabric, Forge, NeoForge, Quilt runtime reuse, and legacy Forge.
- If the wire format changes, deliberately bump the protocol and update every adapter, fixture, mismatch probe, release manifest, and documentation reference together.
- Add tests for disconnect/reset, duplicate hello, timeout, malformed capabilities, overflow, and negotiated-limit enforcement.

Completion criteria:

- No media request is accepted before a valid hello.
- Every adapter enforces the same negotiated bounds and mismatch behavior.
- A protocol change cannot leave a stale adapter or fixture silently using the prior format.

## 7. Apply the confirmed legacy improvements

- Fix `LegacyVideoScreen.initGui()` so rebuilding the UI does not discard unsubmitted search/session text, selection, cursor position, or focus.
- Cover state updates, scrolling, queue toggles, volume changes, screen toggles, and other rebuild paths.
- Keep sound-system reload detection. Measured two-client evidence showed that Paulscode's raw-stream cursor could not satisfy the legacy A/V synchronization gate, so the PCM queue now uses a bounded, lifecycle-owned OpenAL source while preserving positional gain and reload identity checks.
- Add a backend queue-state guard so a stopped or replaced source cannot be restarted by stale buffered state.
- Exercise sound reload, resource-pack reload, world change, disconnect/reconnect, pause/resume, underrun recovery, EOS, and repeated source teardown.
- Preserve the already-hardened legacy envelope and saved-data behavior; extend them with malformed/fuzz cases, schema migration, corrupt/oversized NBT, LRU durability, and reobfuscated restart tests rather than rewriting them.

Completion criteria:

- Forge 1.7.10 passes sustained two-client playback and repeated reload/reconnect/persistence cycles.
- UI rebuilds do not lose in-progress input.
- No duplicate audio, stale playback, or leaked OpenAL resources remain after lifecycle transitions.

## 10. Final completion gate: commit, push, and clean GitHub CI

This is the final goal and must happen only after every preceding phase is complete.

Make reviewed incremental commits and push progress during implementation as
requested. Those intermediate pushes do not close this phase or certify a
release candidate; the final tested commit must still meet every condition below.

The complete [display/stream specification](1.0_CUSTOM_TV_DISPLAY_PLAN.md) is
part of this completion gate. All maintained artifacts must implement its
behavior; required feature scenarios and supplements must be represented in
the final candidate's evidence and maintained CI gates. A build of partial
feature integration or the superseded candidate cannot close this phase.

- Confirm a clean worktree, review the complete diff, and stage only plan-owned changes.
- Commit the hardening in logically reviewable units.
- Run the complete local release gate once more against the final commit.
- Push the exact tested commit.
- Monitor the GitHub Actions run for that SHA until every required job reaches a terminal state.
- Require all of the following:
  - All 16 artifact jobs succeed.
  - All 21 runtime profiles are represented and succeed.
  - No flaky rerun masks an A/V, lifecycle, transport, or runtime failure.
  - The final `1.0 release gate` runs and succeeds rather than being skipped.
  - The downloadable GitHub candidate contains exactly 16 inspected artifacts.
  - Its manifest and artifact hashes match the locally certified candidate.
  - Local `HEAD` equals `origin/main` and the worktree remains clean.

Any failure returns the work to its owning implementation phase. A pushed commit, a successful build, or a mostly-green matrix is not completion.

## Release-readiness definition

Cinemarr may be described as a 1.0 release candidate only when all ten phases and every requirement in the linked display/stream specification are complete and the final exact commit has a fully green GitHub Actions run, a successful expanded aggregate release gate, matching local/hosted artifact hashes, current real-Plex multi-TV/two-client evidence, and clean teardown. Publication and tagging require separate authorization.
