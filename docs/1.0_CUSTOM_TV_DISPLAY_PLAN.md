# Custom TV display controls and independent streams for Cinemarr 1.0

## Summary and agreed behavior

Add independently configurable picture layout, pixel mapping, and stream resolution to custom TVs. Preserve Quick TV construction sizes and preset resolutions. Separate watch-party synchronization from media-stream ownership so each TV can use its own resolution without changing another TV’s quality.

This becomes required 1.0 scope across the maintained **16 artifacts and 21 runtime profiles**, including Forge 1.7.10. It requires a new release candidate and fresh certification after integration with the current hardening work.

| Control | Custom TVs | Quick TVs |
|---|---|---|
| Layout | Fit, Fill, Stretch | Preserve existing controls |
| Pixel mapping | Detailed or One pixel per block | Detailed |
| Resolution | Auto, existing 144p–8K presets, Custom width/height | Existing preset, locked |
| Watch parties | Independent stream per TV; shared playback timeline | Independent stream per TV at its preset |

Defaults are **Fit, Detailed, Auto** for new custom TVs. Existing TVs retain their layout and detailed appearance.

Resolution specifies a **source-aspect-preserving stream bounding box**, not a guarantee of exact encoded dimensions. Source quality, configured server limits, codec rounding, and existing decoder safety limits remain authoritative. Pixel-to-block mode separately determines the final displayed raster.

## 1. Persistent settings, protocol, and interface

### Settings and migration

Introduce shared Java 8-compatible types for:

- Pixel mapping: `DETAILED`, `ONE_PIXEL_PER_BLOCK`.
- Resolution choice: `AUTO`, named preset, or custom width/height.
- TV origin: custom or Quick TV, with an explicit Quick preset identifier.
- A monotonically increasing display-settings revision.

Keep `PresentationMode` as Fit/Fill/Stretch. Pixel mapping is independent of layout.

Persist these settings with the television, rather than inferring an explicit resolution from whether rendition dimensions differ from block dimensions. Preserve settings through controller reactivation, chunk reload, reconnect, and server restart.

Migration rules:

- Existing custom TVs become Detailed/Auto and retain their layout.
- Existing Quick TVs recover their preset from their controller block identity.
- Defer origin classification when the controller chunk is unavailable; do not force-load it or guess from dimensions.
- Preserve existing Quick TV build-mode configuration, including literal mode.
- Invalid saved new fields fall back safely to the relevant custom or Quick defaults. Validate dimensions before allocating anything.
- Increment the world-data schema without discarding existing registrations or construction-recovery records.

### Commands and state

Add an atomic display-settings command carrying the expected settings revision. Validate ownership/operator permission, TV origin, enum values, dimensions, and revision **before any mutation**.

Fix the existing presentation command’s ordering as part of this work: it currently writes presentation settings before rejecting a stale playback generation.

Publish requested settings, their revision, TV origin, effective stream dimensions when known, and per-TV stream status in both idle and active state. Reject attempts to change Quick TV mapping or resolution on the server.

Advance the protocol version from the current version 10, updating all loader adapters and compatibility tests together. Older incompatible clients must receive the existing clear protocol-mismatch rejection.

### Display settings interface

Use a dedicated Display Settings page reached from the controller. Keep it usable at the existing minimum 320×240 scaled viewport.

Provide:

- Fit/Fill/Stretch selection.
- Detailed/One pixel per block selection.
- Auto, named presets, and Custom resolution selection.
- Width and height fields enabled only for Custom.
- Apply, Cancel, validation feedback, and pending/error state.
- Requested resolution, actual stream dimensions, and screen dimensions.
- An explanation that pixel mode’s output resolution equals the screen’s block dimensions.

Custom dimensions accept positive integers from 2 through 8192 per axis; their RGBA frame size must also fit the existing decoded-frame budget. Reject malformed or out-of-range input. Server resolution caps may reduce accepted requests; display the effective limit rather than silently promising the requested quality.

Resolution changes apply during playback without restarting the watch party. Idle and paused TVs save the choice for their next stream start. Cancel changes nothing.

## 2. Playback and rendering architecture

### Separate the watch party from each TV’s stream

Refactor the coordinator and platform video managers into two responsibilities:

| Shared watch-party state | Per-TV media state |
|---|---|
| Session identity, item, queue, position, pause/resume, seek, selected audio/subtitle tracks | Resolution request, stream identity/generation, Plex handle, manifest, transfer grants, viewers, health, recovery, cleanup |

Keep audio/subtitle selection session-wide for 1.0; this feature does not add independent track selection.

Use distinct identities for the shared timeline and each TV stream. Carry both through manifests, segment requests, acknowledgements, health reports, playback state, and client pipeline keys. Include timeline generation in asynchronous completion checks so obsolete media cannot attach after a seek, item change, stop, or retune.

Multiple clients watching the **same TV** share its server stream. Different TVs receive separate streams, including when their settings happen to match. Cross-TV rendition deduplication is outside this implementation.

Preserve positional audio routing by television. Equal session IDs must no longer collapse independent TV pipelines or cause one TV to inherit another’s texture.

### Reconfiguration and synchronization

- Layout and mapping changes affect only the target TV and require no Plex restart.
- Resolution changes replace only that TV’s stream, preserving shared playback state and selected tracks.
- Start replacement media against the authoritative current timeline; account for preparation delay when presenting frames.
- Retain the previous displayed frame during replacement.
- On replacement failure, retain the old working stream where possible, show the error, and expose requested versus active resolution. Do not repeatedly retry permanent failures.
- Shared play, seek, queue advance, pause, resume, and stop fan out to the relevant TV streams.
- Failure of one TV stream must not stop healthy members of the watch party.
- Pausing retains each TV’s last frame and preserves the existing policy of releasing paused transcodes. Applying layout or mapping while paused must redraw that retained frame immediately.

### Capacity and lifecycle

Apply the configured stream cap to active or reserved **TV streams**, rather than sessions. Do not automatically increase it.

Maintain a deduplicated FIFO capacity queue containing at most one entry per eligible TV. A TV must be attached, have viewers, and belong to a playing session to request capacity.

When full:

- Existing playback continues.
- Additional TVs show “Waiting for stream capacity.”
- Freed capacity starts the next eligible TV at the current shared position.
- Removal, retuning, loss of viewers, pause, or stop cancels obsolete requests.
- Rapid setting changes update the pending request rather than enqueueing duplicates.

Preserve bounded replacement/retirement accounting and asynchronous cleanup. Temporary replacement ownership must remain bounded separately from steady-state stream capacity. Preserve unique Plex identities, timeline reporting, serialized stop/report behavior, transfer limits, viewer grace periods, and shutdown cleanup from the current hardening work.

### Resolution policy

Keep current Auto behavior, including its small-screen optimization. Explicit custom or preset resolution overrides that small-screen optimization, so a small Detailed TV can deliberately request higher quality.

Apply source aspect ratio, no source upscaling, server limits, safe even encoded dimensions, and decoder budgets consistently. Report actual dimensions from the resulting media/decoded frame rather than assuming Plex honored the request exactly.

Quick TVs retain their existing preset policy.

### Exact pixel-to-block rendering

Keep the existing decoded-texture path for Detailed mode.

For One pixel per block:

1. Retain the latest presented decoded frame under the existing memory budget.
2. Produce a raster whose width and height equal the TV’s block bounding rectangle.
3. Apply Fit/Fill/Stretch once when sampling that raster.
4. Sample each output cell at its center using deterministic bilinear source sampling. Fit cells outside the image are opaque black.
5. Upload the resulting raster and render with nearest-neighbor filtering and no mipmaps, yielding one uniform color per visible block.
6. Apply the existing mesh mask so holes remain absent.

Do not apply the presentation transform again when drawing the completed block raster.

Place sampling math in shared core code and texture operations in platform adapters. Reuse buffers; update only for a new presented frame or relevant setting/geometry change. Preserve a single batched screen mesh rather than introducing per-block entities or draw calls.

Account for the full bounding raster, including sparse screens, before allocation. Explicitly release retained frames and derived textures on mode changes, stream retirement, resource reload, disconnect, and world shutdown.

## 3. Implementation sequence

1. **Integrate against current hardening work.** Inventory the dirty checkout, preserve unrelated changes, and identify shared family sources and legacy adapters. Update the 1.0 checklist to include this feature and mark earlier evidence as belonging to its recorded candidate.
2. **Add shared settings and migration.** Implement types, validation, persistence, origin classification, and revision handling with focused tests.
3. **Separate timeline and media ownership.** Refactor coordinator lifecycle, capacity accounting, queueing, Plex ownership, and platform managers before exposing the controls.
4. **Update protocol and clients.** Introduce TV stream identities throughout transport and playback; verify permission, stale-work, and disconnect behavior.
5. **Implement rendering and UI.** Add the tested rasterizer, retained-frame behavior, platform texture adapters, and Display Settings page.
6. **Extend acceptance harnesses and documentation.** Add independent quality and exact-raster scenarios to maintained gates, then build and certify a fresh full candidate.

Use family-shared source sets and existing source-drift verification. Avoid unrelated platform expansion or broad cleanup. Each stage must pass its targeted checks before dependent integration work proceeds.

## 4. Tests and acceptance criteria

### Deterministic unit and integration tests

| Area | Required coverage |
|---|---|
| Settings | All choices, invalid input, server caps, odd dimensions, explicit targets matching block dimensions, tiny Auto versus explicit quality |
| Persistence | Old custom and Quick data, unloaded-controller migration, reactivation, restart, corrupt fields, preserved recovery footprints |
| Protocol/security | Round trips, unknown enums, malformed dimensions, unauthorized changes, Quick locks, stale revisions, incompatible protocol |
| Raster output | Independently calculated golden colors for Fit/Fill/Stretch; 4×4, 16×9, odd 17×11, 2000×20, one-cell lines, holes and L shapes |
| Rendering lifecycle | Paused mapping changes, no double transform, nearest sampling, generation changes, reload/disconnect cleanup, bounded allocations |
| Stream isolation | Different resolutions in one party, one stream for multiple viewers of one TV, one TV’s quality change leaving others untouched |
| Synchronization | Shared seek/pause/resume/queue changes, slow startup, late join, reconnect, stale asynchronous completions |
| Capacity | Full cap, fair automatic admission, cancellation, deduplication, current-position admission, bounded replacement and retirement |
| Failure handling | Plex rejection, failed replacement, lost viewer, cleanup failure, server stop, no effect on healthy sibling streams |
| UI | Minimum viewport, no overlapping controls, input errors, Apply/Cancel, read-only permissions, Quick controls, pending/effective state |

Use fake clocks and controlled media factories for synchronization and lifecycle tests; avoid sleep-dependent assertions.

Add modern and legacy platform integration coverage where their adapters differ. Keep all existing lifecycle, transfer, audio, migration, and Quick TV tests passing.

### Runtime and real-Plex acceptance

Extend the runtime harness with a deterministic color/grid fixture and retained original captures. Verify pixel mode by sampling multiple interior points per block and comparing expected raster colors, alongside direct visual review. A decoded-frame hash alone does not prove one-pixel-per-block rendering.

Run a watch party containing:

- Two custom TVs at different requested resolutions.
- A Quick TV retaining its preset.
- Two clients viewing the same TV.
- At least one TV in pixel mode and another in Detailed mode.

Exercise live resolution changes, paused mapping changes, all layouts, capacity waiting/admission, seek, reconnect, resource reload, and shutdown.

Require:

- Verified actual stream dimensions and distinct TV stream identities.
- No sibling stream restart from a local display-quality change.
- Existing A/V synchronization and active-underrun thresholds remain satisfied.
- No unbounded decoder, texture, queue, transfer, or Plex resource growth.
- Correct Quick construction footprint, rollback, persistence, and preset behavior.
- Original captures and physical audio evidence reviewed under the existing acceptance rules.

Run the feature smoke scenario across all 21 profiles. Put deeper capacity/failure and raster supplements on representative legacy and modern profiles, plus every distinct rendering adapter. Retain the existing full real-Plex, recovery, lifecycle, Windows x86-64, and Linux ARM64 requirements.

## 5. Release integration and completion gate

Update user documentation to distinguish block dimensions, pixel mapping, requested stream quality, and effective quality. Document per-TV stream-budget consumption and automatic capacity waiting.

Extend diagnostics with per-TV stream identity, desired/effective resolution, mapping, waiting status, generation, and bounded resource counts. Keep credentials and private media URLs out of diagnostic output.

The feature is complete for 1.0 only when:

- All maintained artifacts implement the same behavior.
- Focused tests and existing regression suites pass.
- Two complete builds produce matching release artifacts.
- The final candidate passes `releaseMatrixGate`, all required supplements, direct visual/audio review, and exact-artifact real-Plex acceptance.
- Final documentation and security scans cover the new output.
- The reviewed final commit passes required hosted CI and downloaded artifact parity checks.

Previous candidate evidence remains historical evidence; it does not certify changed binaries. This plan includes implementation and 1.0 certification, with tagging and publication remaining outside its scope.
