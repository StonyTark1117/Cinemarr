# September 21 implementation and evidence

This record describes work on `codex/complete-1.0`, based on remote `main`
`8e1efda`. It does not declare a release candidate or authorize a tag. The
[hardening plan](1.0_RELEASE_HARDENING_PLAN.md) and

1.0 acceptance contract.

## Implemented corrections

- Display Settings adapters share Java 8-compatible editor state. Apply sends
  the expected current revision, waits for the authoritative next revision,
  retains errors, rejects conflicting updates, and handles permission loss,
  removed TVs and missing replies. Custom dimensions are validated before send.
- A successful settings command publishes the committed state to every current
  viewer of that TV. Layout and mapping changes therefore reach co-viewers
  without waiting for a media replacement.
- Effective dimensions come from the selected HLS variant when advertised;
  unknown dimensions remain unknown. Requested bounding boxes are not reported
  as measured output. Pixel-mode raster allocation is released on return to
  Detailed mode.
- Plex media timestamps use the same whole-second offset sent upstream.
  Fractional request timestamps previously delayed independently started TVs
  by different amounts despite matching their reported playback clocks.
- Terminal and owner-timeline observers distinguish shared timeline identity
  from per-TV media identity. Window discovery reaches its class/tree fallback
  when a name search returns no matches and rejects unmapped candidates.
- The opt-in display scene builds two custom 4×4 TVs and a 144p Quick TV,
  sharing one timeline with three distinct streams. Its observer checks
  independent quality replacement, unchanged siblings, paused mapping/layout
  changes, resume, actual renderer dimensions and the real Display Settings
  entry point at a 320×240 scaled viewport. Captures require direct review.
  Local release and hosted runtime matrices include the display supplement.
- Bounded per-TV diagnostics report timeline/stream generations, requested and
  effective dimensions, settings, waiting/preparing status, viewer counts and
  cached segment/byte counts. Names, media keys, URLs and errors are excluded.

## Shared client transfer pacing follow-up

Normal three-TV resume could exceed the existing per-player server request budget.
Modern and legacy clients now share a fair connection-wide 32-request/second
pacer with a maximum burst of four, one pending window per stream, cancellation
on retirement, and retry timing beginning at actual dispatch. Retirement does
not refill the connection budget. The server limit remains unchanged.
Core fairness/rolling-window tests and modern stream-replacement tests passed;
legacy adapter and fresh runtime checks are being completed. The display
observer now rejects unsolicited segment-request limit errors automatically.

The sixth NeoForge display attempt at `9ee143d` passed stream, resume and
custom-dimension assertions without unsolicited transfer errors, then failed
to open the Quick settings page. Its log records the old custom page opening
before the requested Quick controller was processed: a late asynchronous
screenshot satisfied the old harness acknowledgement. The observer now waits
for the exact requested controller before clicking. Modern controller refreshes
also exclude segment chunks and manifests; those packets do not change widgets
and previously caused repeated widget rebuilds during playback. Run 06 is
retained as failed evidence and did not reach the physical audio comparison.

The raster supplement now retains the original paused RGBA frame under its
rendered SHA-256, with bounded, opt-in output. Both Detailed and pixel mapping
exercise all layouts while paused. `verify-block-raster-capture.py` binds an
original capture and source frame to the same paused TV/revision in `display.json`,
then compares five interior points per visible block against an independently
computed bilinear golden color. Screen corners are explicitly annotated on the
original capture and require direct review; physical occlusions must be named,
and at least three quarters of the cells must remain measured. The original
images are never modified. Six oracle tests include wrong-frame/revision joins,
perspective, expected Fit/Fill/Stretch colors and nonuniform interiors. Runtime
raster results are still pending.
